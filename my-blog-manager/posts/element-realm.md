这次没开新坑，老老实实把自己定的规矩走了一遍：做东西之前先去 GitHub 找现成轮子，能基于现成的改，就不从零手搓。完整走完一遍的产出是 [《元素秘境》](/lab/element.html)，一个 76KB 的单文件落沙沙盒，在这篇博客里点开就能玩。

## 为什么挑了 sandspiel

候选有三个：Chrome 断网小恐龙、粒子裂变 Koalas、落沙沙盒 Sandspiel。最后选 sandspiel，原因挺实在：

- MIT 协议，商用没风险（NC、GPL 的直接排除，这是选型的硬门槛）；
- 玩法上头。沙、水、火、油、酸、蚂蚁、火箭……元素之间是真的会互相反应，水灭火、火点油、酸蚀墙、蚁啃木，这套规则比画面耐玩；
- 内核是 Rust 编译出来的 WASM，性能够打，300×300 的格子每帧更新，桌面浏览器随便 100+ fps。

star 数 16k+，原作者 Max Bittker 至今还在维护。不过原版是个英文的 React 单页应用，带 Firebase 登录、Google 广告、Sentry 监控，这些我统统不要，要的只是那个 wasm 内核。

## 拆的时候，三次差点放弃

### 仓库里根本没有 wasm

克隆下来先傻了：`crate/pkg` 目录是空的，wasm 属于构建产物，被 gitignore 掉了。自己装 Rust 工具链编译吧，一台 Windows 机器装完 rustc 加 wasm-pack 少说半小时，还不一定一次过。我走了另一条路，直接去线上扒官方正在跑的版本。

用 Playwright 打开 sandspiel.club，开着 Network 面板看它到底加载了什么，很快锁定一个带 hash 的 wasm 文件，39.9KB。抓下来一看 magic bytes 是 `\0asm`，就是它。

这次之后我算记住了：想要现成产物，盯着 Network 面板看"实际在跑什么"，比在仓库里翻"应该怎么构建"快得多。

### 胶水层自己写

官方 JS 是 webpack 打出来的 1MB chunk，九成是 React、Firebase、Sentry。全内联进单文件等于背一麻袋砖头跑步，没必要。我的做法是只取 wasm，胶水层手写。

在浏览器里 inspect wasm 的导入导出表，发现它只要 3 个导入函数：`Math.random`、一个抛错函数、externref 表初始化。最后那个的实现是从官方 chunk 里抠出来的，四行代码，往表里依次塞 undefined、null、true、false。整个 glue 写完，20 行。

### 被 GLSL 编译器教育

渲染层用的是官方一段 fragment shader，依赖 glslify 的三个包（hsv2rgb、simplex noise、random）。我把这些函数内联手写的时候连踩三个坑：

- WebGL1 的 GLSL 不允许函数重载，vec3 和 vec4 两版 `mod289`/`permute` 只能起不同名字；
- simplex noise 抄错一行，`vec4 norm = ... (p0*p0 + p1*p1 + ...)`——vec3 加 vec3 还是 vec3，赋给 vec4 直接类型爆炸。标准写法是 `vec4(dot(),dot(),dot(),dot())`，四个标量拼一个 vec4；
- 网上搜到的报错行号跟源码对不上，最后写了段 evaluate，把页面里实际编译的 shader 源码抽出来数行，才定位到出错那行。

## 手感，是最好玩的部分

移植完其实已经能跑了，276fps，元素交互也都对。正准备收工，自己上手玩了一下，不对——鼠标一拖，一整列沙"唰"地齐齐下坠，像一块铁板掉下去，根本不是沙子该有的样子。

回头翻 Rust 源码找根源：wasm 的 `paint` 是一次性把圆形区域写满，同一帧出来的沙粒随机种子几乎相同，整块沙的行为自然一模一样。原版不明显，是因为画布小、笔刷小；世界被我扩到 2.4 倍之后，这个缺陷就被放大成了没法装看不见的怪相。

修的时候没动 wasm 一行，全在 JS 侧重写笔刷：

- 软笔刷：不再整圆填满，改成圆内按大概 40% 的密度逐格撒点，每粒沙走 wasm 内部随机数独立取值，下落抖动各管各的，沙流就参差了；
- 按住聚积：pointer 按住不动时每 80ms 撒一小把（密度 28%），沙在指尖慢慢堆起来，再成股滑落，比较接近"手里攥着一把沙"的手感；
- 固体另说：结界、黑曜岩、枯木、复制魔印保持实心填充，建筑类元素要的是棱角，不是颗粒感；
- 开场动画也跟着改成"细沙如雨"，从天而降铺出沙丘，顺便当了游戏的第一眼演示。

验证办法很土：在浏览器里模拟"按住 1.2 秒"，按时间点统计沙粒数，16 粒、67 粒、166 粒，基本是线性长上来的，说明沙真是一点点漏出来的，不是一整块成型。

## 顺手做的其他事

- 世界扩容：300×300 的正方形改成按窗口比例的矩形（桌面大概 22 万格，2.4 倍面积）。wasm 的 `universe_new(w,h)` 本来就支持，麻烦的是纹理上传的列主序转置和鼠标坐标映射得自己修；
- 性能：逐像素 simplex noise 换成轻量 hash，canvas 不乘 devicePixelRatio，纹理用 texSubImage2D 增量上传。软件渲染（SwiftShader）从 1fps 拉到 112~276fps，真机只会更宽裕；
- 中文化：20 种元素全部改名，流沙、圣泉、狱炎、荆棘、魔种、黑曜岩、玄冰、熔核、毒沼、瘴雾、噬魂蚁、菌毯、复制魔印、咒焰火箭、结界、虚空……配上暗黑幻想风的毛玻璃 UI；
- 单文件化：wasm 转 base64 内嵌，外部依赖全砍，加上 MIT 版权声明，最后 76KB 一个文件丢进 `public/lab/`，Next 静态托管，点开就玩。

## 收尾

整套"找轮子改造"的流程走下来，大概是这么一条线：先看协议、活跃度和审美做选型，抓线上产物绕开构建链，只取内核、手写胶水，能拆多薄拆多薄，然后一定自己上手玩，手感不对就修到对，最后单文件部署。

最耗时间的反而是那个"一列沙整齐下坠"。量化指标全绿和手感对不对，到底是两回事，不上手摸一下根本暴露不出来。

链接放这儿了：[作品页](/lab/element.html)。去画一笔狱炎，再泼一捧圣泉，看蒸汽升起来那一下，今天踩的坑就都值了。

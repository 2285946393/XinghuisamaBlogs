前几天在 B站刷到一条《如何用 Codex 做剪辑，保姆级教程》，6.8 万播放。评论区一片"已学会"，我看了半天没看懂——剪辑软件不是有手就行吗，让 AI 剪是剪什么？

搜了一圈才明白，**现在说的「AI 剪辑」不是 AI 生成视频，是让 AI 操作剪辑软件**。

## 先把两件事分清

我原来的理解是：把素材丢给模型，出来一条成片。实际不是这样。

- **AI 生成视频**：文生视频、图生视频，Seedance、可灵那一类。产出的是素材。
- **AI 剪辑**：剪辑软件开着，让 agent 通过 MCP 协议读时间线、下操作。产出的是成片。

后者的玩法大概是：达芬奇 21.1 官方开放了 MCP 接口，剪映也有社区做的 MCP server，Claude Code、Codex 这类 agent 接上去之后，可以直接说"把这段卡到鼓点上""按标记把画面铺上去"，它自己去操作时间线。

我本来想照着搭一套剪映 MCP，后来算了——我连剪映都没装。

## 挑了个专门剪口播的

翻 GitHub 的时候看到 `ai-jian-koubo`，482 星，中文项目。它的定位很窄但很实在：**口播视频的粗剪**。

口播最费时的不是剪，是"找哪里该删"——重复重说、卡壳、口癖、长停顿。这东西的思路是：转录全文 → AI 标出该删的片段 → 起一个本地网页让你在波形上确认 → 导出工程文件。

它不直接剪视频，只负责"想清楚剪哪里"，最后一刀交给剪辑软件。转录走火山引擎，有 40 小时免费额度。

装它的过程比想象中折腾。这项目是按 macOS / Linux 写的，在 Windows 上踩了三个坑。

## 三个 Windows 坑

**一、`file:` 前缀**

脚本抽音频用的是 `ffmpeg -i "file:$VIDEO_PATH"`。Mac 上没问题，Windows 上直接报 `No such file or directory`。

原因挺隐蔽：Git Bash 会自动把 `/c/Users/...` 这种 POSIX 路径转成 Windows 路径再传给原生程序，但**加了 `file:` 前缀之后，转换就被跳过了**。ffmpeg 是原生 Windows 程序，读不懂 `/c/Users/...`。

去掉前缀，或者全程传 `C:/...` 格式，就好了。

**二、python3 是个假的**

`python3 -c "print(1)"` 跑出来一片空白，不报错也不输出。

查了半天，命中的是 `WindowsApps` 目录下的微软商店占位符——没从商店装过 Python 的话，这个占位符就在那杵着，执行起来什么也不干。

解法是在 `~/bin/` 放个垫片转发到真实 Python。Git Bash 的 PATH 里 `~/bin` 排在 `WindowsApps` 前面，能盖住它。

**三、curl 的证书吊销检查**

转录请求全部失败，curl 退出码 35。加上 `-v` 才看到真正的报错：

```
schannel: next InitializeSecurityContext failed:
CRYPT_E_REVOCATION_OFFLINE (0x80092013) - 证书吊销服务器已脱机
```

Windows 的 curl 走 Schannel，连 TLS 时要检查证书吊销状态，查不到就直接拒绝连接。国内访问字节的接口经常查不到。

加 `--ssl-no-revoke` 跳过就行。但这参数是 Schannel 专有的，Mac 上的 OpenSSL 版 curl 不认识，硬加会让脚本在别的系统上崩。所以改成了先探测 curl 版本再决定加不加。

三个坑修完，转录终于通了。

## 然后发现：我没有东西可剪

转录成功，识别出 31 个字。我愣了半天才反应过来——**我根本没有口播素材**。

翻了一遍 Videos 目录，能用的只有一条 9 分 50 秒的录屏，内容是操作我自己的作品展馆，点进各个作品看一遍，再退回来。

既然工具都装好了，那就拿它干点正事：**给 28 个作品剪一条演示片**。

面试的时候，面试官看到简历上写"28 个 Web 作品"，他不可能一个个点开看。但一条几分钟的视频，几十秒就能扫完。

## 但这条录屏没法直接剪

问题在于它的结构：

```
展馆 → 点进作品 A → 看一会 → 返回展馆 → 点进作品 B → ...
```

展馆页、页面跳转、加载等待全在里面。而且有的作品我自己觉得"太拉"，不想放进去。

这类活运动量检测帮不上忙——展馆首页那个极光流体封面比谁都活跃。只能靠**场景切分 + 人工挑选**。

于是写了个脚本：用 ffmpeg 的场景检测找出镜头切换点，把过短的合并掉，切成 53 个候选片段，每个抽 3 张缩略图，生成一个网页。我在网页上扫一遍，勾掉不要的，给要的起个名。

选完 27 段，合并首尾相接的，剩 21 段，7 分 08 秒。

## 想自动认作品，失败了

给每段加标题字幕之前，我动了个歪心思：`assets` 目录里有 31 张按 slug 命名的作品截图，能不能用图像比对自动认出每段是哪个作品？

写了个脚本，用 HSV 颜色直方图加网格平均色做特征，拿每段缩略图去和 31 张参考图比。跑完一看结果很漂亮——每个片段都匹配上了，还带置信度。

然后我拿手填的结果对了一遍：**21 段只蒙对 3 个**。

更离谱的是，匹配度 0.886（最高分）的那段，我猜"抉择回响"，实际是"边界千年"；0.802 那段猜"弹球磁砖"，实际是"节奏抽卡"。**高分也全是错的**，置信度这个指标本身就没意义。

原因想明白了：参考截图是 1440×810，录屏是 2546×1344，浏览器视口尺寸不一样，页面是响应式的，版面自然对不上。颜色分布又不够有区分度，一堆深色主题的作品互相混淆。

结论：作品名这种东西还是让人来填。我做了个命名页，21 行，每行配缩略图和输入框，填完导出。

## 最后一步：烧字幕

字幕又踩了个坑。

第一次我把 `drawtext` 挂在 `trim` 后面，结果字幕小了一号还偏下。原因是滤镜作用在源片分辨率上（2546×1344），最后缩到 1920 宽的时候字号跟着等比缩了。

正确做法是 `concat → scale → 再叠字幕`，用 `enable='between(t,t0,t1)'` 按累计时间控制每段显示哪行字。

还有个 Windows 特有的坑：ffmpeg 的 `fontfile` 参数**不认带盘符冒号的绝对路径**，`C:/Windows/Fonts/xxx.ttc` 会被过滤器解析器当成参数分隔符。绕法是启动 ffmpeg 时把工作目录切到字体目录，只按文件名引用。

## 成品

片头 4 秒，正片 7 分 08 秒 21 段（每段左下角标了作品名），片尾 4 秒。

最后成片 **7 分 28 秒，1920×1014，209 MB**。从 9 分 50 秒的原始录屏里剪掉了 2 分 42 秒的展馆页和页面跳转。

## 一点感想

整条流水线走下来，最花时间的不是剪，是**搞清楚"哪里该剪"**。转录、场景检测、缩略图审核页，本质上都在解决同一个问题：让"决定删什么"这件事变得能一眼看清。

另外就是，AI 工具在 Windows 上的水土不服比想象中严重。那个口播工具本身写得挺扎实，但三个坑没有一个是它的逻辑问题，全是平台差异。修完之后我在它的 SKILL.md 里补了一节 Windows 注意事项，免得下次再踩。

至于那套图像比对——写的时候挺兴奋，验证完发现全错。但我觉得比写对了更有价值：**知道什么方法不行，比多一个能用的小工具管用**。

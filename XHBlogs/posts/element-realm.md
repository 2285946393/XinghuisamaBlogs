这次不开新坑，把规则走完：**做东西之前先去 GitHub 找现成的轮子，基于现成的改，禁止从零手搓**。这个信条第一次完整落地，产出是[《元素秘境》](/lab/element.html)——一个 76KB 单文件、能在这篇博客里直接点开玩的落沙沙盒。

## 选轮子：为什么是 sandspiel

候选有三个：Chrome 断网小恐龙、粒子裂变 Koalas、落沙沙盒 Sandspiel。我选了最后一个，理由很直接：

- **MIT 协议**，商用无风险（NC/GPL 直接排除，这条是选型的硬门槛）；
- 玩法上头。沙、水、火、油、酸、蚂蚁、火箭……元素之间真实交互，水灭火、火点油、酸蚀墙、蚁啃木，物理规则比外观更耐玩；
- 内核是 Rust 编译的 WASM，性能有底子——300×300 的格子每帧更新，桌面浏览器轻松 100+ fps。

star 数 16k+，原作者 Max Bittker 至今还在维护。轮子本身是英文的 React 单页应用，带 Firebase 登录、Google 广告、Sentry 监控。这些统统不要，要的是那个 wasm 内核。

## 拆轮子：三次差点放弃的瞬间

### 1. 仓库里根本没有 wasm

克隆下来一看，`crate/pkg` 目录是空的——wasm 是构建产物，被 gitignore 了。要么自己装 Rust 工具链编译（一台 Windows 机器装完 rustc + wasm-pack 少说半小时，还未必一次过），要么……去线上扒官方正在跑的。

我选了后者：Playwright 打开 sandspiel.club，开 Network 面板，看它真实加载了什么。答案是一个带 hash 的 wasm 文件，39.9KB。抓下来，magic bytes 是 `\0asm`，就是它。

这一步的教训：**要产物，看 Network 面板比看仓库结构快得多**。仓库给的是"应该怎么构建"，Network 面板给的是"实际在跑什么"。

### 2. 手写 wasm-bindgen glue

官方 JS 是 webpack 打包的 1MB chunk，90% 是 React/Firebase/Sentry。全部内联进单文件等于背着一吨砖头跑步。反其道行之：只取 wasm，胶水层自己写。

用浏览器 inspect wasm 的导入导出表，发现它只要 3 个导入函数：`Math.random`、抛错、externref 表初始化。最后一个的实现是从官方 chunk 里抠出来的——四行代码，往表里依次塞 undefined/null/true/false。手写 glue 总共 20 行。

### 3. GLSL 编译器教会我做人

渲染层是官方的一段 fragment shader，依赖 glslify 的三个包（hsv2rgb、simplex noise、random）。内联手写这些函数时连踩三个坑：

- WebGL1 的 GLSL **不允许函数重载**——vec3/vec4 两个版本的 `mod289`/`permute` 得写成不同名字；
- 抄 simplex noise 抄错一行，`vec4 norm = ... (p0*p0 + p1*p1 + ...)`——vec3 加 vec3 还是 vec3，赋给 vec4 直接类型爆炸。标准写法是 `vec4(dot(),dot(),dot(),dot())`，四个标量拼一个 vec4；
- 网上搜的报错行号对不上源码，写了段 evaluate 从页面里把实际编译的 shader 源码抽出来数行，才定位到那行。

## 造轮子没造的部分：手感修复

移植完成、276fps、元素交互全对，正准备收工时上手玩了一下——**手感不对**。鼠标一拖，一整列沙"唰"地整齐下坠，像一块铁板掉下去，完全不是沙子该有的样子。

翻 Rust 源码找根源：wasm 的 `paint` 是一次性把圆形区域写满，同一帧出现的沙粒随机种子几乎相同，于是整块沙的行为一模一样。原版不明显是因为画布小、笔刷小；世界扩大到 2.4 倍后，这个缺陷被放大成无法忽视的怪相。

修法不动 wasm 一行：JS 侧重写笔刷——

- **软笔刷**：不再整圆填充，改为圆内按约 40% 密度逐格撒点，每粒沙由 wasm 内部随机数独立取值，下落抖动各自独立，沙流自然参差；
- **按住聚积**：pointer 按住不动时每 80ms 撒一小把（密度 28%），沙在指尖缓缓累积，然后成堆滑落——就是"手里攥着一团沙"的手感；
- **固体例外**：结界/黑曜岩/枯木/复制魔印保持实心填充，建筑类元素要的是棱角，不是颗粒感；
- 开场动画同步改成"细沙如雨"，从天而降铺出沙丘，顺便成了游戏的第一眼演示。

验证方式很土但有效：浏览器里模拟"按住 1.2 秒"，逐时间点统计沙粒数——16 粒 → 67 粒 → 166 粒，线性增长，说明真的是一点点漏出来的，不是一坨成型。

## 还做了什么

- **世界扩容**：300×300 正方形 → 按窗口比例的矩形（桌面约 22 万格，2.4 倍面积），wasm 的 `universe_new(w,h)` 原生支持，代价是修好纹理上传的列主序转置和鼠标坐标映射；
- **性能**：逐像素 simplex noise 换成轻量 hash、canvas 不乘 devicePixelRatio、纹理用 texSubImage2D 增量上传。软件渲染（SwiftShader）从 1fps 拉到 112~276fps，真机更不用愁；
- **中文化**：20 种元素全部重命名——流沙、圣泉、狱炎、荆棘、魔种、黑曜岩、玄冰、熔核、毒沼、瘴雾、噬魂蚁、菌毯、复制魔印、咒焰火箭、结界、虚空……配合暗黑幻想的毛玻璃 UI；
- **单文件化**：wasm base64 内嵌、砍掉全部外部依赖、加 MIT 版权声明，最终 76KB 一个文件放进 `public/lab/`，Next 静态托管，点开即玩。

## 结语

这次流程走完，"找轮子改造"的完整链路是：**选型（协议/活跃度/审美）→ 抓线上产物绕过构建链 → 只取内核手写胶水 → 拆到能拆的最薄 → 上手玩，手感不对就修到对 → 单文件化部署**。

最费时间的不是移植，是那个"一列沙整齐下坠"的手感修复——量化和直觉的差距，只有真正上手玩才暴露得出来。AI 看截图可以糊弄，手指骗不了人。

今天是从一句"找点适合我这个简历的项目"开始的。

翻自己的简历，看着看着发现一个问题：五个项目，极光流体、元素秘境、深渊塔、人生重开、通信调制实验室——**全是图形、游戏、创意类**。

面试官看完大概会想：这人玩得挺花，但能不能写业务代码？

缺的不是第 29 个炫酷页面，是一个能证明**工程能力**的东西。所以方向定成：做一个企业级后台。

## 先找轮子

按自己定的规矩，先去 GitHub 找现成的。候选看了几个，最后挑中 `art-design-pro`，5.9k 星，MIT 协议。

选它的理由很实在：

- MIT，商用没风险（NC、GPL 直接排除，这是硬门槛）
- 设计感在线，毛玻璃、圆角、动效都调得挺细
- 组件齐全——表格、图表、权限、设置面板都有，不用从零搭
- 最近还在更新

原版是个通用的后台模板，带一堆演示模块：用户管理、角色管理、菜单管理、文章管理、帮助中心。这些我统统不要，要的是它的**框架能力**。

## 改造：先把它变成"我的"

第一件事是品牌化，不然打开还是一眼模板：

- 系统名改成「有花无实 · 创作中台」
- 主题色换成我简历上那个玫瑰粉 `#B5486C`
- Logo 用 Pillow 画的——粉紫渐变圆角方块，中间一只小鲸鱼
- 头像换成站长立绘

然后是把演示数据换成真的：**34 个作品**，slug、体积、技术栈都是从线上 `/lab/*.html` 抄下来的，不是我编的。

页面做了四个：

- **总览看板**——作品总数、累计浏览、累计点赞、本月新增，配 30 天趋势折线、类型分布环形、热度排行、技术栈频次、最近动态
- **作品管理**——关键字 / 分类 / 状态组合筛选，分页表格，新增 / 编辑 / 单删 / 批量删，加一个 CSV 导出
- **数据分析**——分类占比、技术栈雷达、单文件体积 Top 8、浏览量-点赞散点、近 12 个月上线节奏，六类图表
- **关于本项目**——功能说明、工程实践清单、目录结构

最后把模板自带的演示模块从菜单里全摘了，只留自己的东西。菜单干净了，整个站才像"我的产品"而不是"我改的模板"。

## 两个真实的坑

### 一、图标全消失了

改完跑起来一看，页面上所有图标都没了，控制台一堆请求失败。

原因是 Iconify 默认在**运行时**从 `api.iconify.design` 拉图标数据，这域名国内访问不了。它不像字体那样有本地回退，拉不到就是一片空白。

官方给的解法是装离线图标集。但图标集是整包下载的——我看了下 `@iconify-json/ri` 的 `icons.json`，**1MB 出头**，六个图标集加起来 3.5MB。全塞进首屏，为了几个图标背这么大一包，不划算。

于是写了个脚本：扫源码里真正出现过的 `prefix:icon-name`，只把用到的图标从图标集里抽出来，生成一份精简集合。

```bash
pnpm build:icons
# 扫描 210 个文件
#   ri            引用 54 / 命中 54
#   system-uicons 引用  1 / 命中  1
# 已写入 offline-icons.json：57 个图标 / 14.6 KB
```

**3.5MB → 14.6KB**，而且离线可用。代价是新增图标要重跑一次脚本，但脚本是幂等的，跑一次几秒钟。

### 二、登录竟然依赖别人的服务

准备部署的时候顺手翻了下 `.env.production`，发现 `VITE_API_URL` 指向的是 `m1.apifoxmock.com`——一个第三方接口 mock 平台。

也就是说：**这个后台的登录功能，依赖一个跟我毫无关系的免费服务**。它哪天挂了、限流了、或者删了那个项目，我的站就进不去了。

模板作者这么写是为了让人 clone 下来就能跑，但我不能把一个演示站的核心功能挂在别人家。

改法是把认证接口本地化：保留原来的函数签名和返回结构（`fetchLogin` 返回 `{token, refreshToken}`，`fetchGetUserInfo` 返回用户信息），内部换成模拟实现，账号密码校验、角色分配都在本地做。

这样既去掉了外部依赖，将来接真后端也只要换函数体，页面代码一行不用动。

## 现在的样子

线上：**creator-studio-orcin-nine.vercel.app**，演示账号 `Super` / `123456`。

代码在 `projects/creator-studio/`。顺手写了 README，把"值得一看的实现点"列了出来——路由 meta 驱动菜单、两级权限（菜单级 roles + 按钮级 `v-auth`）、接口层收口、状态收敛、图标离线化。

## 一点感想

改模板这件事，最花时间的不是写代码，是**把别人的东西变成自己的**。

一开始我觉得改个名字换个色就叫改造了，实际上不是。真正让它变成"我的"，是换上自己的真实数据、砍掉不需要的演示模块、把依赖换成自己能控制的。做完这些，打开页面才不会有"这是谁的模板"的违和感。

另外就是，那个 apifox mock 的事提醒我：**clone 下来的项目，`.env` 和外部依赖要当成风险点看**，不能因为它能跑就默认它没问题。

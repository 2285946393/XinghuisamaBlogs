我电脑里攒了一堆 API Key。来源五花八门：群里别人发的"免费鸡蛋"、公益站注册送的、还有自己瞎逛看到的。

问题是它们**从来不写在显眼的地方**——散在三个配置文件里，有的能用，有的早就死了，我自己也分不清哪个是哪个。

今天干脆让 AI 把它们全拉出来，挨个测一遍。

## 先说结果

七个 Key，**两个活的**。

| Key 来源 | 结果 |
|---|---|
| 群里发的新鸡蛋 | 额度已用完 |
| 群里发的老鸡蛋 | 能用（但慢） |
| 两个 blameupstream | 令牌无效 |
| 96110 中转 | 站长跑路了（404） |
| 本地 M365 网关 | 没开机 |

那个"新鸡蛋"挂掉的时间点特别准——**发下来大概三小时就烧完了**。跟我估的完全一致。

免费的东西就是这样，手快有手慢无。

## 第一课：状态码 200 不代表能用

这是我今天最该记住的一条。

测到某个站的时候，它 `/models` 返回 200，`/chat/completions` 也返回 200，响应时间 300 毫秒，漂亮得不像话。

我当时就说"这个能用"。

后来细看返回内容——

```html
<!doctype html>
<html lang="en">
  <head>
    <link rel="icon" type="image/png" href="/logo.png" />
```

**它返回的是它自己的网页。**

那个站根本不是 API，任何路径都给你吐首页 HTML。而我的测试脚本只看了状态码是 200，就当成成功了。

> 教训：测接口一定要看**返回内容**，不能只看状态码。

同一个错误其实很常见——很多网站把不存在的路径重定向到首页，而不是老老实实返回 404。

## 第二课：免费站的高峰期会排队

有个公益站，19 个模型，测的时候一半报这个：

```
模型服务当前并发繁忙，请稍后重试
```

我一开始以为是坏了，准备划掉。后来隔了十几秒重发，**通了**。

它不是坏了，是**在排队**。用的人太多，服务端直接把你挡回来让你稍后再试。

这东西跟"限速"还不一样：

- **限速**是明确的配额——"你一分钟只能问 5 次"，超了就是超了，得等满一分钟
- **排队**是看运气的——同一分钟里重发两次，可能第一次挂第二次就过了

所以遇到 503 别急着判断死活，**多试几次**。

## 第三课：同一个东西，不同站叫不同名字

现在的模型流行"先思考再回答"。你在界面上看到的是它先嘀咕一段推理过程，然后才给正式答案。

这段推理过程在数据里是单独一个字段。问题是——**各家的字段名不一样**：

- 大多数站叫 `reasoning_content`
- AMD 那个站叫 `reasoning`

我按前者的名字去解析 AMD 的返回，结果内容全空，一度以为它坏了。

还有一次更冤：我给某个模型设了 100 字的输出上限，它把**全部 100 字都花在思考上**，还没开始写正文就被截断了。表现出来就是"返回 200 但内容是空的"。

把上限调到 800，正文立刻就出来了。

这两次都是**看起来像故障，其实是我没搞懂它的规矩**。

## 顺便发现：Codex 改名了

这事跟 Key 没关系，但今天顺手撞上的。

我想装 Codex 桌面版，在微软商店里搜"Codex"，什么都搜不到。折腾半天才搞明白——**它现在挂在 ChatGPT 底下了**。

官方文档里那个 Codex 的产品 ID，现在商店里显示的名字是 **ChatGPT**，发布者还是 OpenAI。商店描述里写得很直白：

> For software development, Codex is the coding agent in ChatGPT.

所以搜不到是正常的，**搜 ChatGPT 才对**。

安装倒是卡住了（报错 `0x8024001e`，大概是商店通道的问题），这块留着下次弄。

## 现在能用的三条路

折腾一晚上，最后手上留了三个站，一共十个模型：

- **公益站 A**：5 个模型，最全，主力
- **AMD 开发者站**：2 个 Qwen，快
- **公益站 B**：3 个模型，高峰期要重发

三条路换着用，基本不会卡死。哪条限速了就切另一条。

## 最后

今天其实没做出什么东西——就是测了一堆 Key，接了几个站，装 Codex 还翻车了。

但我觉得这几条教训比"成功装好某个软件"更值钱：

**状态码会骗人，内容不会。**
**看不懂的报错，先怀疑自己是不是没搞懂规矩。**

至于那些死掉的 Key——留着吧，万一哪天额度又恢复了呢。

反正放在配置文件里也不占地方。

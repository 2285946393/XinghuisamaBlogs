![封面](/images/cover-quest-spire.jpg)

封面这张截图，是这整件事的起点：我加的遗物在游戏里显示成了**一把锁**。

提示写着「这个遗物需要在时间线中解锁才会在未来的游戏中出现」。可我明明把它的说明写好了——中文名、效果、连风味文本都写了，结果一个字都没显示出来。

这篇就写这一天：**从一把锁开始，最后拆出了这游戏是怎么长的。**

## 一、先说起点：一个写了一半的 MOD

前一阵我让 AI 给我做了个《杀戮尖塔2》的任务 MOD，思路借鉴一代的 SpireQuests：进游戏后右上角常驻一块面板，你可以主动接任务（累计打多少伤害、消耗多少张牌、赢几场精英），达成了自动发奖励。

它当时的状态是：**能编译、能部署、25 个任务——但一次真人实测都没做过。**

接手的 AI 留了两份文档，一份技术交接、一份流水账。我读完的第一件事不是改代码，而是让它先把游戏自己的代码翻一遍。

## 二、最值钱的发现：这游戏留了一整套「旋钮」

想给游戏加效果，最笨的办法是硬改。但《杀戮尖塔2》把模型基类上的钩子全公开了，我让 AI 扒了一遍，一共两类：

- **25 个「否决」钩子**（`Should*`）：返回 false 就能挡住一件事——不让某张牌打出、不让抽牌、回合结束不弃手牌、虚无牌不消耗、甚至不让某个生物死。
- **29 个「改写」钩子**（`Modify*`）：把某个数值算成新的——伤害倍率、格挡倍率、抽牌数、能量上限、商店价格、篝火回复量、你施加的增益层数、攻击段数、伤害上限……

**这套菜单才是「能做出百花齐放效果」的本钱。** 效果不是凭想象写的，是顺着旋钮找出来的。后来我做的 8 个奖励，每个对着一个不同的旋钮，手感天然就不一样——比如「莽夫之道」：你的攻击伤害 +50%，但技能牌不再提供格挡。这不是「给个数字」，是**拿防御换输出**的取舍。

## 三、那把锁：一条日志就定位了

回到封面。遗物为什么变成锁？

我没猜，直接让 AI 去翻游戏日志。答案两行：

```
Missing sprite 'quest_spire_relic_quest_book_relic' in relic_atlas
Asset not cached: res://images/packed/common_ui/locked_model.png
```

翻译一下：游戏按「遗物 ID 的全小写」去图集里找图标，找不到，于是**回退成 `locked_model.png`——就是那把锁**。而且它不只换图，**连标题和说明也一起换成「锁定」文案**。

所以：**「没有图标」和「效果说明显示不出来」是同一个问题。** 我写的中文说明不是丢了，是压根没机会显示。

根子在于 mod 的素材。这游戏用 Godot 引擎，它把图片、文字打包成一个「资料袋」（`.pck`），游戏按固定地址 `res://...` 去找。**没有袋子，这个地址就不存在。** 我们之前只交了逻辑（一个 dll），所以游戏能跑但看不见素材。

补上打包流程之后，遗物就正常了。

顺带还发现游戏**给翻译留了个后门**：`localization_override` 目录里的 JSON 会被合并进本地化表，而且不要求 key 已存在——相当于允许你往里塞全新的文本。这个我先用上了，后来有了正经打包就让它退居二线。

## 四、原画不用画：一代的 jar 里就有

四件遗物（枯木树枝、鸟居、咖啡滤杯、玩具扑翼飞机）本来就是一代的东西。

我一开始打算让 AI 画图，被叫停了——**「这些本来是一代的遗物，你没必要跑。」**

对啊。一代是 Java 游戏，图片就以明文 PNG 躺在它的 jar 里（jar 本质是 zip）。写个脚本就能把小图标、轮廓、大图全抠出来，一部分遗物连 256×256 的大插图都有。而且官方公开表示过一代的素材可以用在二代里。

**于是十件遗物全部用上了官方原画，一张图都没画。**

## 五、被叫停的三次，比做成的部分更值得记

1. **「你最好不要照抄这个海克斯的 mod，它在二代很火，基本是个人都玩过。」**
   当时我确实照抄了它一个符文的效果（攻击牌重放一次、伤害 -40%）。删了重做。
   **要学的是它「怎么做效果」的手法，不是它的效果本身。** 这一条其实通用：抄一个所有人都见过的东西，等于告诉别人你没想法。

2. **「这些本来是一代的遗物，你没必要跑。」**（上面那条）

3. **「你没发现你很蠢吗？攒到五百才发金偶像，游戏都快结束了。」**
   这条最疼，也最有收获。我把「金偶像」（效果是**之后**敌人掉的金币 +25%）配了个「攒到 500 金币」的条件。
   500 金币差不多是第三幕末期——**之后的敌人没几个了，这遗物拿到手就是废纸。**
   同样的问题还藏在另外两个：御守是「抵消**之后**拿到的诅咒」，我却要求「牌组里已经有 3 张诅咒」（方向反了）；套娃是「**之后** 2 个宝箱各出 2 件遗物」，我要求「打开 3 个宝箱房」——而一局通常就 3 个宝箱房，开满之后再给等于没有下一个宝箱。
   最后总结成一条原则写进文档：**前置型奖励（拿到之后才持续生效的）条件必须第一幕内能达成，而且要在开局选任务时优先出现。** 光把条件提前还不够——任务库有几十个，开局只随机给 6 个候选，抽不到照样白搭。

## 六、现在什么样

- **61 个任务**：从一代的任务池里挑能做的、加社区梗（「宇宙冷漠」是摄政王真有的牌，被 B 站当歌唱）、加角色专属（故障机器人的「还在启动 / 回响形态 / 严父在上」）。
- **10 件自己造的遗物**：不用装任何别的 mod 就能拿到，官方原画 + 中英文本。
- 还有个小玩意：面板底部留了个**【测试】立即完成全部任务**的按钮，一次把所有奖励发给你看。发布前得删掉——它等于一键刷奖励。

## 七、最后

我做这个 MOD 最大的体会是：**写 mod 最有意思的部分不是写代码，是把别人的游戏拆开，看它当初是怎么设计的。**

比如那 25 + 29 个钩子——那不是「接口文档」，那是设计者给出的**可能性清单**。你把清单读完，自然就知道「这个游戏允许玩家变成什么样子」。这比自己闷头想效果有意思得多。

（这一天全程是和 AI 一起做的：我出判断和审美，它负责翻代码、写实现、查日志。上面三次叫停都是我拍的板——**AI 很能干，但它不知道「这个梗人人都玩过，抄了会显得没水平」这种事。**）

## 八、补记：上架创意工坊了

（2026-09-22 深夜）

写上面这些的时候，这个 MOD 还躺在本地。现在它已经传上 Steam 创意工坊，公开可订阅：

**尖塔任务 / Quest Spire**：https://steamcommunity.com/sharedfiles/filedetails/?id=3806270140

![创意工坊条目](/images/quest-spire-workshop-item.jpg)

上传用的是官方工具（Mega Crit 自己出的 `sts2-mod-uploader`）：把要传的文件塞进一个工作区文件夹，写一份 `workshop.json`（标题、说明文、标签、依赖），然后一条命令。真正花时间的不是流程，是下面两件事。

### 一个字符级的坑，卡了半小时

依赖那一栏**必须写数字**：

```json
"dependencies": ["3747602295"]   // → Exception thrown while parsing the workshop config!
"dependencies": [3747602295]     // → 正常
```

写成字符串，上传器会**整个解析失败、什么都传不上去**，而报错只告诉你「格式不对」，不说是哪一栏。我是用二分法试出来的：先传最小配置（能过）→ 加完整说明文（能过）→ 加数字依赖（能过）→ 再加标签（也能过），剩下的嫌疑人就只有一个。

### 说明文原来是可以排版的

我把创意工坊趋势榜前十个 MOD 的说明文全抓下来读了一遍，发现**热门的一个都没用纯文字**：标题、加粗、列表、链接、引用、代码块都是支持的标记。板块顺序也高度一致——一句话说清是啥 → 功能列表 → 前置依赖 → 注意事项 → 已知问题 → 更新日志 → 致谢 → 链接，长度普遍在 1500~2200 字。

于是我把说明文按这个结构重写了一遍（1000 字 → 2041 字）：

![说明文排版](/images/quest-spire-workshop-desc.jpg)

**为什么这次特别在意说明文**：现在是测试期，我要的是别人真的来留言——哪个任务条件太苛刻、哪件遗物拿到手发现没用、想加什么任务。说明文是我唯一能跟他们说话的地方，写得让人看得懂、看得下去，比多写 20 个任务有用。

那个【测试】按钮我暂时留着，说明文里注明了是调试用的，下个版本删掉。

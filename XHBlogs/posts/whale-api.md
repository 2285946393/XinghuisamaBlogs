刚做完那个 Vue3 后台，紧接着又刷到一条 B站视频：《0基础搭建 AI 中转站，和朋友分享会员服务》，7 分 25 秒，13 万播放。

评论区一片"已学会"。我看了两遍，越看越觉得这事得先查一下再说。

## 先搞清楚视频在做什么

教程的流程是：装 Docker → 部署 Sub2API → 用 Cloudflare Tunnel 把本地服务发到公网。

Sub2API 这个项目在 GitHub 上 41.8k 星，不算小。但翻它 README 第一段就看到这个：

> ⚠️ **服务条款风险**：使用本项目可能违反 Anthropic 等上游服务商的条款。

官方还专门声明了一句："从未授权任何个人或组织基于本项目进行任何形式的商业运营。"

再看它的赞助商列表——住宅代理（主打"降低多账号关联风控概率"）、批量注册工具、收款网关、各种中转站平台。这套东西凑在一起，真实用途已经很清楚：**批量转卖 AI 订阅账号的额度**。

所以真的那套我不做。不是因为技术难，是因为：搭起来号大概率被封，而且学到的技能对前端简历一点用没有。

## 但产品形态可以抄

不碰真服务，不代表不能做这个"产品"。

一个 AI 中转站的界面长什么样？我把它真实的前端目录拉下来数了数，结构很清楚：

- **官网**——首屏宣传、支持的模型和价格、实时状态、套餐、FAQ
- **用户控制台**——余额、API 密钥管理、用量统计、模型广场、账单、调用日志
- **管理后台**——数据看板、渠道管理、用户管理、全站日志

这套东西**纯前端就能做**，数据用假的，不接任何真服务。而且它正好是个练手的好题目：有 CRUD、有图表、有权限、有表单校验，业务还是我熟悉的 AI 领域。

于是决定：做一个同款产品形态的演示站，叫「鲸云 API」。

## 换个技术栈

上一个项目用的是 Vue3 + Element Plus。这个我特意换成了 **React + TypeScript + Vite + Tailwind**。

理由有两个：一是简历上能写"两种框架都做过"，二是两个项目摆在一起能看出技术广度，比再做一个 Vue 后台有说服力。

底子挑了 `brainwave`（MIT），一个深色科技风的 AI 落地页模板。但它有个问题：**全是 JSX，没有类型**。

所以第一步是全量重构成 TSX——30 多个文件，加上 `tsconfig`、类型定义。这一步没什么技术含量，但做完之后 `tsc --noEmit` 能跑通，改代码的时候心里踏实很多。

页面一共做了 12 个：

```
官网 /          首屏（API 调用示例可切 cURL/Python/Node）+ 模型广场（12 个模型带价格）
                + 能力介绍 + 实时状态（30 天可用率条形图）+ 价格 + FAQ
控制台 /console 概览 / API 密钥 / 用量统计 / 模型广场 / 调用日志 / 账单充值
管理端 /admin   数据看板 / 渠道管理 / 用户管理 / 全站日志
```

## 两个坑

### 一、字体从 Google 拉的

模板的 `index.css` 第一行是：

```css
@import url("https://fonts.googleapis.com/css2?family=Sora:wght@300;400;600&display=swap");
```

Sora 是那个设计感的来源之一，但 `fonts.googleapis.com` 国内访问超时。浏览器不会报错，只会**静默回退**到系统字体——页面看着"差不多"，但气质就是不对。

解法是把字体下下来自托管。只取 latin 子集（中文走系统字体），三个字族六个 woff2 文件，加起来 **127KB**。写 `@font-face` 的时候顺手带上 `unicode-range`，浏览器就只会按需下载对应子集。

### 二、首屏背了一麻袋

第一次构建完看产物：主包 **841KB**。

大头是 recharts（图表库）——但那 12 个页面里，只有控制台和管理端用得上图表，官网首页根本不需要。访客打开首页却要下载一整个图表库，不划算。

改法是路由级代码分割：官网同步加载，控制台和管理端用 `React.lazy()` 按需拉。

```jsx
import Landing from './pages/Landing'          // 首屏要用的，同步

const ConsoleUsage = lazy(() => import('./pages/console/Usage'))   // 按需
const AdminDashboard = lazy(() => import('./pages/admin/Dashboard'))
```

构建完再看：主包 **389KB**，410KB 的图表库被切成了独立 chunk，只有真正进后台才加载。

## 顺手做的

- **服务层收口**——15 个接口（模型、密钥、日志、渠道、用户、统计）全放在 `src/lib/api.ts`，函数签名和返回结构对齐真实后端，页面只关心 loading 和数据
- **`useAsync` hook**——把"加载中/成功/失败/手动刷新"四态收敛成一个 hook，处理了组件卸载后不 setState 的问题，页面里没有一处手写三件套
- **列配置驱动的表格**——`DataTable` 用 `Column<T>[]` 描述列，泛型保证 `render(row)` 的类型安全
- **固定种子随机数**——mock 数据用 mulberry32 生成，刷新页面图表不会乱跳

## 一点感想

这条视频教的东西我一个字没照着做，但它给了我最有用的东西：**一个产品的形态长什么样**。

很多时候缺的不是技术，是不知道"要做成什么样"。把真实产品的页面结构扒下来，剩下的就是自己填。

另外就是，看到"手把手教你 XXX"的教程，先花五分钟查一下它在做什么、靠什么赚钱、有没有风险。**这一步省不得**。B站评论区一片"已学会"的时候，可能没人去看那个项目的 README 第一段。

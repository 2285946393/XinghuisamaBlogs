上一篇（[我给《杀戮尖塔2》写了个任务 MOD](/posts/quest-spire-mod)）写的是第一天：怎么从一把锁开始，把素材管线拆出来。

这篇写后面这几天，主要是**被玩家按在地上摩擦**的部分。现在它在创意工坊上，**111 条任务**。

## 一、这几天加了什么

- **任务 61 → 111 条**：分成累计、条件、玩法、角色专属、B 站梗、乐子、流派七类。
- **10 件遗物**：枯木树枝、鸟居、咖啡滤杯、玩具扑翼飞机、金偶像、御守、齿轮工艺品……效果按一代原版复刻。
- **16 个「随身物」**：挂在任务册上的永久效果，比如手不释卷（每回合多抽 1 张）、砍价高手（商店 -30%）。
- **38 条数值重算**：拿着游戏真实数据改的——一轮大概 2800 点敌人总血量、24 场杂兵战、800 到 900 金币收入。把"根本做不到"的目标砍下来，比如把"承伤 600 点"改成算**挨打的总伤害**（含被格挡掉的），不然坦克流一辈子做不完。

## 二、第一个 bug：buff 翻倍，一行加法写错

玩家报：「装了你的 MOD，怪物和我自己的增益 / 减益层数会翻倍。」

我有个效果想写"你施加的增益 +1 层"。游戏给的那个钩子是**加算**的：它把返回值加到原来的数上。而我返回的是"原来的值 + 1"：

```csharp
return amount + 1m;   // 结果变成 num += num + 1 → 2 倍再加 1
return 1m;            // 正确：只加 1
```

改完顺手把另外 10 个同类钩子全审了一遍，只有这一个错。

**这类错误的特点是它不会崩，只是数字静悄悄地不对**——所以只能靠玩家报。这也是为什么我后来越来越在意"日志里能不能看出证据"。

## 三、联机不同步：我把它重做了两遍

**第一遍**我想当然地让"每个客户端给自己那位玩家发任务册"。结果主机和客机对"谁有册子"的看法不一致，一进房间游戏就判数据不同步。

修法是抄游戏的：**给所有玩家都发一遍**。游戏自己的开局逻辑就是这么干的——各端算出来的东西完全一样，不需要联网对账。

但玩家补充了一个关键信息：**他们的玩法就是 SL**（存档 → 退游戏 → 重进）。于是第二个问题浮出来：任务进度原本只存在本机，而多人局的存档是**主机**存的那一份。主机手里"你那本"是空的 → SL 回来任务全变了。

这次我拆了创意工坊里另一个做得好的 MOD（《海克斯符文》），看它怎么处理。结论是用**游戏自己的「玩家选择」通道**——就是"弃牌选哪张""遗物三选一"用的那一套：

1. 开局时，每个客户端都按同一顺序给每位玩家预留一个选择编号（各端编号一致）；
2. 你自己挑完，把结果广播出去；
3. 其他客户端收到后，写进**那位玩家自己的任务册**。

这样每台机器的任务列表一致，主机存下去的也是全的。

顺带一个收获：**「刷新候选」做成纯本机行为最省事**——刷新只发生在你这台，广播出去的只有最后挑中的那几个任务，天然不会不同步。

## 四、最费劲的一个：「放弃一局重开，旧任务还在」

这个我查了**三轮**，前两轮方向全错。

- **第一轮**：以为是静态变量没跟上，就把"先发册、再点亮接取按钮"的顺序改了。
- **第二轮**：给账本绑上"属于哪一局"的标记，不属于当前这局的一律当空。
- 玩家说：**还是有。**

第三轮我不猜了，直接去翻游戏日志。新局开头是这两行：

```
[QuestSpire] QuestRunner: 已绑定本地任务册（本局任务 3 条）。
[QuestSpire] Run started: quest book granted to 1 player(s).
```

**新开局拿到的那本任务册里，直接带着 3 条旧任务。** 不是显示错了，是数据真的跟着过来了。修法就一行：新局拿到册子后强制清空，并在日志里留痕。

教训：前两轮我都在修"显示"，因为那个假设更符合直觉。**日志一读，假设当场就塌了。** 以后碰到"数据不对"，先确认数据本身，再谈时序。

## 五、「展望未来」不发奖：奖励队列只有一个出口

玩家报：新任务"展望未来"（带着 250 金币进商店，扣钱换化学X 和一张 X 费牌）好像根本没发奖励。

日志里它其实**完成过**：

```
[QuestSpire] 战斗中完成「展望未来」，奖励等这场打完再发。
[QuestSpire] QuestPanel unmounted.          ← 玩家紧接着放弃了这局
```

它明明是**商店**触发的，却被判成"战斗中"，奖励进了等待队列；玩家一放弃整局，队列跟着遗物一起没了——**奖励静默丢失**。

修法：进新房间时只要不在战斗里，就立刻把攒着的奖励补发掉。

顺便立了条规矩：**凡是"先攒着、等条件满足再发"的队列，都必须有多个出口**（战斗胜利、离开战斗、进新房间）。只挂一个出口，就等于给玩家准备了一个丢奖的坑。

## 六、发奖励要给"玩家名下的卡"

另一个玩家报：X 费牌的奖励界面弹出来了，但牌**点不中**，连调试按钮都救不回来。

原因是我把从卡池里捞出来的**公共卡模型**直接塞进了奖励界面——界面能渲染，但选中那一步拿到的不是"你的卡"。正确写法是先转成玩家名下的卡：

```csharp
var owned = picks.Select(m => owner.RunState.CreateCard(m, owner)).ToList();
```

《海克斯符文》里也是这么写的。

## 七、创意工坊的两个硬限制（都踩过）

- **封面必须横版。** 竖版 1024×1440 直接被拒。
- **简介上限是 8000 字节，不是 8000 字。** 中文一个字 3 字节，所以差不多只能写 2600 个汉字。我加了四条更新日志就顶到 8051 字节，上传直接失败——把陈年日志压成一行才过。

现在上传前会先量一次字节，不再数汉字。

## 八、和一个态度上的修正

我一开始给玩家的回复里写的是「麻烦重启游戏更新后再试一次」。

后来想明白了：**玩家没有义务给我当测试员。** 他花了钱、花了时间，报个 bug 是在帮我。我该做的是"谢谢你报的这个，我查了、修了"，而不是把验证的工作再派回给他。

所以后面的回复改成三段：感谢反馈、说清修了什么、之后再碰到随时说一声。

## 九、还没做的

- **随身物做成真遗物**：现在它们是挂在任务册上的隐藏效果，做成真遗物后会直接进遗物栏、悬停能看说明。美术需求已经写成文档丢给画画的同学了（12 件 × 3 张图）。
- 三件一代遗物还没实现：机械臂、套娃、突变酵素。
- 联机里"进商店再接任务"暂时关着——那个时机没法安全同步，硬做会让游戏自己"选哪张牌"卡住。
